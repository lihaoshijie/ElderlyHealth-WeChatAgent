# M1 测试手册 —— 银龄智护 · 体征三级预警 / 家庭联动 / 用药依从性

> 适用代码：elder-agent（后端 Agent）
> M1 范围：① 体征记录自动三级预警（绿/黄/红，红色通知子女）② 家庭守护绑定 + 健康日报/漏服提醒推送 ③ 用药依从性分析
> 测试方式：真机微信对话端到端（需要两个微信号：长辈 A、子女 B）

---

## 0. 测试前准备（一次性）

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 0.1 | 创建数据库并建表 | `mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS elderly_health_db DEFAULT CHARACTER SET utf8mb4"`，再 `mysql -uroot -p elderly_health_db < sql/schema.sql` | 无报错；`SHOW TABLES` 能看到 `family_bind`、`health_alert` 两张新表 |
| 0.2 | 配置密钥 | `cp src/main/resources/application.example.yaml src/main/resources/application.yaml`，填入 MySQL 密码、`llm.api-key`（阿里百炼/DashScope）、iLink 配置 | — |
| 0.3 | 启动 | `./mvnw clean package -DskipTests` 后 `java -jar target/elderly-health-agent-0.0.1-SNAPSHOT.jar` | 控制台出现微信登录二维码 |
| 0.4 | 两个微信号各自与 bot 建立会话 | 微信号 A（长辈）、微信号 B（子女）分别扫码/添加后各发一句任意消息（如"你好"） | 两个号都能收到 bot 回复；**子女号必须至少成功对话一次**，bot 才能向子女主动推送 |
| 0.6 | **推送前提（重要）** | 每次**重启应用后**，先让「子女」向 bot 随便发一句话（如"你好"），再让长辈触发推送 | 日志出现 `守护消息已发送`；若子女从未发言，SDK 没有其会话 token，推送必然失败 |
| 0.5 | （可选）改短定时器便于观察 | 在 `application.yaml` 把 `family.daily-report-cron` 临时改为每 2 分钟 `0 */2 * * * *`、`family.missed-med-cron` 同理 | 重启后生效 |

## 1. 家庭守护绑定（用例 F1）

> 目标：长辈生成邀请码 → 子女绑定 → 双向可见。

| # | 角色 | 在微信里发送 | 预期 |
|---|---|---|---|
| F1-1 | 长辈 A | `让我的孩子绑定我，接收我的健康日报` | bot 返回 6 位邀请码 + 引导语，例如"已生成家庭绑定邀请码：483920…" |
| F1-2 | 子女 B | `绑定家人 483920`（用 F1-1 拿到的码） | bot 返回"绑定成功 ✅…" |
| F1-3 | 长辈 A | `我的守护人有哪些` | 返回守护人列表（子女 B 的 ID） |
| F1-4 | 子女 B | `我守护的长辈` | 返回长辈 A 的 ID |
| F1-5 | 长辈 A | `我的守护人有哪些` | 重复出现（验证未重复绑定） |
| F1-6 | 数据库 | 自查 | `SELECT elder_user_id, guardian_user_id, status FROM family_bind;` 有一条 `ACTIVE` |
| F1-7 | 长辈 A | `解除守护人 <子女ID>`（ID 用 F1-3 返回值） | 返回"已解绑该守护人"；再查库该行 `REMOVED` |

**备注**：若 bot 没听懂，可加前缀命令感的话术，例如先发"绑定家人"再发 6 位码。误绑自己会被拒绝（"不能绑定自己"）。

## 2. 体征三级预警（用例 V1 ~ V4）

> 目标：录入体征自动分级；黄色仅提示本人；红色立即推送子女。

| # | 角色 | 在微信里发送 | 预期分级 | 子女是否收到 |
|---|---|---|---|---|
| V1 | 长辈 A | `记录血压 126/78` | 绿（正常），无预警文案 | 否 |
| V2 | 长辈 A | `记录血压 152/95` | 黄：【黄色提示】…血压 152/95 | 否 |
| V3 | 长辈 A | `记录血压 185/112` | 红：【红色预警】…已通知您的家人 | **是**（子女 B 收到"⚠️ 健康预警…请尽快关注…血压 185/112"） |
| V4 | 长辈 A | `记录空腹血糖 17.2` | 红：预警 + 通知子女 | 是 |
| V5 | 长辈 A | `记录体温 38.2` | 黄：提示关注 | 否 |
| V6 | 长辈 A | `记录血氧 88` | 红：预警 + 通知子女 | 是 |
| V7 | 数据库 | 自查 | `SELECT vital_type, vital_value, level, notified_guardian FROM health_alert ORDER BY id DESC LIMIT 5;` 红色记录 `notified_guardian=1` |

**阈值参考**（`VitalAlertService` 内可调）：血压红 ≥180/110、黄 ≥140/90；血糖红 ≥16.7 或 <2.8、黄 ≥7.0；心率红 ≥130 或 ≤40；体温红 ≥39、黄 ≥37.3；血氧红 ≤90、黄 91–94。绿色不落库 health_alert。

## 3. 用药登记 + 依从性分析（用例 M1 ~ M4）

| # | 角色 | 在微信里发送 | 预期 |
|---|---|---|---|
| M1 | 长辈 A | `登记用药 硝苯地平 每次1片 早上8点 还剩20片` | 建档成功，并创建每日 08:00 服药提醒 |
| M2 | 长辈 A | 到点收到提醒后回复 `吃了硝苯地平` | 服药打卡成功，余量减 1 |
| M3 | 长辈 A | `我这7天吃药依从性怎么样` | 返回依从性报告：药名 + 实际/7 天 + 依从率 |
| M4 | 长辈 A | `最近30天依从性` | 返回近 30 天统计（统计区间上限 90 天） |
| M5 | 长辈 A | 当天不打卡，等 cron（见 0.5）或直接发 | 若 21:00 定时器触发：子女 B 收到"💊 漏服提醒…今日尚未打卡：硝苯地平" |
| M6 | 数据库 | 自查 | 健康数据在 `health-data/<长辈ID>.json` 中：`medications`、`medicationLogs` 有记录 |

**注**：依从率口径 = 最近 N 天内"实际有打卡的天数 / N 天"，同一天多次打卡按 1 天计。

## 6. 常见问题

- **子女收不到推送**：子女微信号必须与 bot 有过成功会话（0.4）。**若本机运行多个 bot 账号（如 main / bot2），长辈和子女分别加的是不同 bot**——系统会按"子女最近在哪台 bot 上说过话"自动选用对应 bot 推送，请确认子女发过消息后再触发推送；检查 `family_bind` 是否 ACTIVE；看后端日志 `守护消息已发送/失败`。
- **bot 没识别"绑定家人"**：确认走的是 LLM function calling 而不是直接命令；可改说"我要让家人绑定 / 生成绑定码"。仍不行，查看日志是否命中域过滤（`域过滤: 匹配域=…`），`家庭守护` 关键词包含"绑定/家人/守护/日报"等。
- **health_alert 落库失败但主流程正常**：提示文字仍会出现（落库被 try/catch），请先确认 0.1 已建表。
- **想清空测试数据**：删 `health-data/*.json` + `DELETE FROM family_bind; DELETE FROM health_alert;`（仅测试库）。
