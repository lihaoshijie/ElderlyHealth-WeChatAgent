## 一、基础能力

| 消息类型 | 功能 | 位置 |

| 文本消息 | LLM Function Calling 智能路由 | WeChatBotService |

| 线程池 | 16 线程处理微信消息 |

## 二、AI Agent 核心

### 2.1 Agent Loop（ReAct 循环）

- 最大 3 轮工具调用
- Token 预算保护（100K 上限）
- 总超时保护（90s）
- 同轮工具并行执行（≥2 时 CompletableFuture 并发）
- 工具结果截断（10000 字）
- 去重拦截（同工具+同参数）
- 搜索工具自动降级（百度⇄Google 互切）
- selfCheck 自检（回复含"可能/也许"时）

### 2.2 工具分域

根据用户输入关键词匹配，只发送相关域工具：
- 闲聊："你好" → 5 个通用工具
- 天气："杭州天气" → 6 个天气+时间工具
- 旅游："杭州攻略" → 13 个旅游工具
- 12306/B站：命中时返回全部（MCP 工具名运行时确定）

### 2.3 Skill 系统（13 个）

工具调用后自动激活行为规则，注入 LLM 上下文：

| Skill | 规则 |
|-------|------|
| 搜索 | 结果含网址时自动生成二维码 |
| 天气 | 并行查天气+空气质量 |
| 旅游 | 按流程查景点→生成攻略 |
| 图片 | 生成后不重复描述 |
| 文件 | 结果以 TXT 返回 |
| 热搜 | 追问时调 ai_news，不编造 |
| 健康饮食 | 查食物时同时查营养+建议 |
| 待办提醒 | 增删后自动确认列表 |
| 语音 | 用完自动关，不主动开 |
| 生日命理 | 并行排盘+流年+五行 |
| 快递 | 中通/申通必须手机号尾号 |
| 记忆 | 主动保存用户信息 |

## 四、RAG 检索系统

### 4.1 文档入库

```
上传文件 → 提取文本 → 切块（1000字/100字重叠）→ Embedding 向量化 → 存入 doc_embeddings
```

### 4.2 检索流程

- 空库跳过（TTL 缓存 60s）
- 全文索引粗筛 + 向量精确匹配
- 注入限长（≤1500 字）

### 4.3 新管线（RagPipelineService，待接入）

- 闲聊短路（"你好""再见"不跑检索）
- 预检拦截（相似度 < 0.45 跳过）
- 单路混合检索（向量 0.6 + BM25 0.4）

## 七、性能优化记录

| 优化 | 效果 |
|------|------|
| LangChain4j OpenAiChatModel 替代手写 HTTP | 内建重试/Token统计 |
| 动态工具分域 | Token 8500→2500（闲聊） |
| 工具并行执行 | 多工具场景省 50% 时间 |
| 工具结果截断 | 多轮 token 不膨胀 |
| 文件内容截断（6000 字） | 文件不入历史 |
| MySQL 异步落库 | 不阻塞回复 |
| RAG 空库 TTL 缓存 | 免 embedding API |
| 线程池 4→16 | 并发提升 |
| selfCheck 收紧 | 减少 LLM 调用 |
